# Печать оргструктуры — для разработчиков

Модуль открывает окно предпросмотра печати оргструктуры. Слева в окне настройки, справа листы.
Сохранение в PDF и печать идут через системный диалог браузера (`window.print`).
Модуль самостоятельный и не зависит от разметки и стилей страницы.

## Файлы

Берите файлы целиком и не правьте их изнутри. Иначе ваша правка потеряется при следующем
обновлении. Всё, что может понадобиться менять, вынесено в настройки вызова (см. ниже).
Если чего-то не хватает, напишите нам.

| Файл | Что это |
|---|---|
| `print.js` | ES-модуль, экспортирует `openPrintPreview` и `closePrintPreview` |
| `print.css` | Стили окна и листов. Подключайте как обычную таблицу стилей |
| `Fonts/*.otf` | Шрифты TT Commons Pro: 5 файлов |

В архиве есть папка `example/`: страница печати на выдуманной структуре в формате `component.php`
(50 подразделений, 355 человек со случайными именами). Откройте её через любой локальный веб-сервер,
например `python3 -m http.server` в корне архива и затем `http://localhost:8000/example/`.
С `file://` ES-модули не работают.

Шрифты `print.css` ищет по относительному пути `Fonts/…` от самого `print.css`. Если шрифты лежат
в другом месте, поправьте пути в пяти строках `@font-face` в начале `print.css`. Это единственное
место, которое можно менять под вашу раскладку файлов.

После каждого обновления меняйте метку версии в ссылках (`print.css?v=…`, `print.js?v=…`),
иначе браузер возьмёт старый файл из кэша.

## Подключение

Как сейчас в вашем `print-page.js` на странице печати. Добавляется только `banner`:

```js
import { openPrintPreview } from './print.js?v=20261109';   // ?v= — сменить при обновлении файлов

const payload = window.STRUCTURE_PRINT || {};
const groupId = payload.head && payload.head.id ? payload.head.id : '';
const target = groupId
  ? '/company/structure/detail/?group=' + encodeURIComponent(groupId)
  : '/company/structure/';

function launch() {
  openPrintPreview(payload, {
    onClose: () => { window.location.href = target; },
    banner: isAdmin,   // ваш признак админа; false — без формата «Баннер»
  });
}

if (document.readyState === 'loading') document.addEventListener('DOMContentLoaded', launch);
else launch();
```

`print.css` подключается на этой странице обычной ссылкой: `<link rel="stylesheet" href="…/print.css?v=20261109">`.

### Настройки вызова — `openPrintPreview(payload, opts)`

| Ключ | По умолчанию | Что делает |
|---|---|---|
| `onClose` | — | Вызывается после закрытия окна предпросмотра |
| `banner` | `true` | `false` прячет формат «Баннер» (например, если он только для админов). Кнопка «Сбросить» его не возвращает |

`closePrintPreview()` закрывает окно программно.

## Данные — `payload`

Тот же объект, что собирает `component.php`.

```js
{
  title: 'Группа строительных компаний',   // название группы — в шапке листа
  logo: 'https://…/logo.svg',             // необязательно; без него шапка без логотипа
  graph: {
    nodes: [{ members: [подразделение, …] }, …],   // контейнер из нескольких — подразделения «рядом»
    edges: [{ source: id, target: id }, …],        // родитель → ребёнок
  },
  head: {
    label: 'Группа строительных компаний',
    sup: [человек, …],                    // руководители блока — верхний уровень листа
    tree: [{ id, children: [...] }, …],   // только порядок подразделений (ORDER_IN_GROUP)
  },
  board: { … },                           // необязательно, см. ниже
}
```

**Подразделение** (`members[]`):

| Поле | Что это |
|---|---|
| `id` | GUID подразделения. Регистр не важен: сравнение без учёта регистра |
| `label` | Название |
| `sup`, `subSup` | Руководитель и второй руководитель (человек) |
| `participants` | Участники с ролями. Записи с `role: 'Руководитель'` пропускаются: это `sup` |
| `team` | Сотрудники отдела |
| `isAPosition` | Узел-должность (например, «Заместитель генерального директора»): печатается карточкой человека с серой плашкой должности |

**Человек**: `{ guid, name, fullName, pos, photo, inits, displayPhoto }`.
- `fullName` — полное ФИО, `name` — сокращённое (переключатель «ФИО полностью»).
- `pos` — должность.
- `inits` — инициалы для заглушки аватара. Если поля нет, инициалы берутся из первых букв двух первых слов ФИО.

**Аватары.** Фото из данных не используются, у всех заглушки с инициалами. Так решил заказчик.
Цвет заглушки вычисляется из ФИО, поэтому у одного человека он всегда один и тот же. Включить
фото: константа `PP_DATA_PHOTOS = true` в `print.js`.

**Совет директоров (`board`)** — необязательное поле: уровни над руководителями блока. Состав —
тот же, что вы показываете на главной:

```js
board: {
  label: 'Совет директоров',
  members: [человек, …],   // у человека можно задать role — подпись вместо должности
  executive: человек,      // исполнительный директор, отдельный уровень под советом
}
```

В «Ветках» совет есть всегда, но по умолчанию снят. Без поля `board` этих уровней просто нет.

## Что видит пользователь

- **Формат:** A4–A0, горизонтально или вертикально, и «Баннер» (см. ниже).
- **Как печатать:** целым листом или частями A4/A3 для склейки плаката (с нахлёстом и метками).
  Отдельная галочка «Каждая ветка — на своём листе»: сначала общая схема, потом по листу на ветку.
- **Раскладка:**
  - «По отделам»: колонка делится только между отделами первого уровня.
  - «Авто»: отделы целиком, сотрудники сеткой.

  Галочка «Заполнять всю ширину» растягивает структуру на ширину листа. В «По отделам» с ней
  подразделения разворачиваются вширь.
- **Уровни, ФИО полностью, аватары, сотрудники, выбор веток с поиском.**

Текст на листах не мельче 7 pt. Если структура не помещается, она продолжается на следующих листах
того же формата. В «По отделам» листы продолжения идут без шапки и без повторённых названий, их
можно склеить в одну картинку. В «Авто» на листах продолжения повторяются названия колонок
с пометкой «продолжение».

### Баннер

Одна страница по размеру структуры, текст ровно 12 pt, пропорция как у листа A в выбранной
ориентации. Нужен для заказа баннера в полиграфии. Что передать полиграфии:

- PDF из браузера в RGB. Полиграфия переведёт его в CMYK, фирменный красный может немного сместиться.
- Текст и линии векторные и при любом увеличении остаются чёткими. Растровые только логотип и
  фото, если они есть.
- Acrobat не открывает страницы больше 5,08 м по стороне. На такой случай в окне есть
  предупреждение. Решение — убрать сотрудников, часть веток или уровней.

## Браузеры

Раскладка проверена в движках Chrome, Safari и Firefox. Все сочетания настроек дают одинаковый
результат.

- **Chrome, Edge, Firefox** берут формат и ориентацию бумаги со страницы (`@page size`).
  Пользователь только выбирает «Сохранить как PDF» или принтер.
- **Safari** формат и ориентацию со страницы не берёт: печатает на бумагу, выбранную в окне печати
  (по умолчанию A4, книжная), и лист обрезается. Модуль распознаёт Safari и пишет под кнопкой печати,
  какой формат бумаги, ориентацию и масштаб 100 % выбрать. Форматов крупнее A3 в списке Safari
  обычно нет. Для них подпись советует открыть печать в Chrome, Edge или Firefox или печатать
  частями A4/A3.

Если у вас есть свой текст или справка по печати, рекомендуйте Chrome, Edge или Firefox.

## Производительность

Время пересчёта при смене настройки:
- обычная структура — десятые доли секунды;
- группа на ~1100 сотрудников со всеми сотрудниками на листах — около 1–1,5 с;
- структура на 3000 сотрудников на A4 (100+ листов) — 2–3 с.

На листе продолжения лежит только его кусок структуры, поэтому сотня листов не означает сотню
копий в памяти.

## Особенности данных, которые мы заметили

В выгрузке начала ноября 2026 (`structure_api`, таблицы команд, пользователи):

- **216 записей команд** ссылаются на подразделения, которых нет в выгрузке структуры. Больше всего
  в третьей таблице команд: 102 из 284. Эти люди в печать не попадают.
- **207 сотрудников из команд** не нашлись среди пользователей, поэтому у них нет ФИО.
- **3 подразделения без родителя в выгрузке:** «Дирекция по строительству №2»,
  «Инженерно-техническая дирекция», «Финансово-экономический отдел». Они висят отдельно от дерева,
  и печать ставит их верхним уровнем, рядом с карточками блока.
- **4 записи с нулевым GUID подразделения** (`00000000-…`).
- **11 GUID** записаны у разных людей. Печать различает людей по `guid`, поэтому, если двое с одним
  GUID окажутся в одном отделе, второй не покажется.

Печать на всё это не падает, но структура выходит не такой, как задумано. Лучше поправить в базе.

## Проверено

- **Настоящие выгрузки:** три группы целиком и каждая ветка по отдельности, уровни 2–4 и все.
- **11 искусственных выгрузок с крайними случаями:**
  - названия и ФИО на несколько строк, слова без пробелов;
  - 600 человек в отделе, 30 колонок, 9 уровней вложенности;
  - подразделения без руководителя, без названия, без людей; ФИО из одного слова;
  - повторы людей, сироты, перемешанные и раздутые команды;
  - структура на 3000 сотрудников.
- **Все сочетания настроек:** раскладки, «Заполнять всю ширину», сотрудники, ветки по листам,
  ориентации, A4–A0, баннер.

**Что проверялось на каждом листе:**
- текст не мельче 7 pt;
- ни одна строка не разрезана краем листа;
- текст не вылезает за плашку, карточку или поля и не налезает на другой текст;
- шапка стоит по полям;
- листы заполнены, пустых листов нет;
- ни один сотрудник не потерялся и не повторился.
